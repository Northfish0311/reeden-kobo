## 2. 三条优先级代码路径

### 路径 A：合盖休眠（优先级 1）

**文件 / 函数链**

```
scripts/run.sh                       启动 host，创建 logs/current.log，exec >> launcher.log
  -> src/host.c  主循环 (while !app_quit)
     -> src/cover.c : cover_open()      扫描 /dev/input/event0..31
     -> src/cover.c : cover_event()     边沿去抖 / SYN_DROPPED 重同步
     -> src/cover.c : cover_settled()   返回 COVER_CLOSED / COVER_OPEN
     -> src/host.c : edge==COVER_CLOSED -> set_sleep(&touch,true)
     -> src/host.c : 1.4s 后关前光 -> power_worker_start("%s/power.sh")
     -> src/power_worker.c : power_worker_start() = power_worker_command(path, "suspend")
     -> scripts/power.sh : exec >> $APP/logs/power.log，执行 echo mem > /sys/power/state
  -> 开盖：cover_settled() COVER_OPEN -> host.c 置 power-cancel / set_sleep(false)
```

**关键触发条件（源码）**

- `no-sleep-cover` **不存在**（`access(no_cover, F_OK) != 0`）才调用 `cover_open`；存在则打印 `[cover] disabled by user preference`，盖检测停用、电源键仍可用。
- 传感器必须匹配：`EV_SW` 的 `SW_LID`，或名称为 `gpio-keys` / `ntx_event0` 且具备 `KEY_F1` 且**不含** `KEY_A` 的 `EV_KEY` 节点（`cover.c:source_type`），排除 USB/蓝牙键盘；未知传感器不猜测。
- 边沿去抖 150 ms（`cover.c:observe` 设 `due = now + 150000000ULL`）；`SYN_DROPPED` 后 `resync()` 用 `EVIOCGSW`/`EVIOCGKEY` 重同步。
- 只有 `ready && acquired`（首帧已到 + `state/handoff` 存在）后才 `open("/dev/input/event2")` 并 `EVIOCGRAB` 独占。
- `set_sleep(true)` 设 `cover_at = now + 1400000000ULL`（**1.4 秒**）才关前光（`write_number(brightness, 0)`）并允许启动 helper。
- `state/power-screen-only` 标记存在时（`host.c:513`）**根本不启动 `power.sh`**，只锁屏。
- `power.sh` 的第一个实参固定为 `suspend`：`power_worker.c:power_worker_start(path) -> power_worker_command(path, "suspend")`。另外两种调用是 `restore`（`set_sleep(false)` 恢复 Wi-Fi）与 `native`（退出回原生的 Wi-Fi 交接），日志分别是 `invoked arg=restore` / `=native`。

### 路径 B：电源键休眠（优先级 2）

**文件 / 函数链**：`host.c` 主循环 → `open("/dev/input/event2", O_RDONLY|O_NONBLOCK)` + `ioctl(EVIOCGRAB,1)` → `poll(fds[2])` → `EV_KEY / KEY_POWER` 事件 → `set_sleep()` → 与 2.1 相同的 1.4 秒关前光 → `power_worker_start(power.sh)` → `power.sh suspend` → `power.log`。

**真实日志**：
- 启动：`[power] exclusive power key acquired`（`host.c:467`）。
- 按键释放：`[power] key release`（`host.c:557`，条件 `ev.value==0 && power_down`；按下 `value==1` 只置 `power_down=true`，不打日志）。
- 若 `sleeping && power_worker>0`：`[power] wake requested; waiting for hardware restoration`（`host.c:558`），同时 `state_file("power-cancel",true)`。
- 否则 `set_sleep(&touch, !sleeping)` → `[power] screen locked; engine retained` 或 `[power] resumed same engine and book`。
- `power.log` → `[power] invoked arg=suspend` → `[power] entering mem` → `[power] mem returned=0`（**任务点名的验收入口**）。

**注意**：盖传感器可能与电源键是同一个 input 节点（`cover.shared_power`），此时 `cover_event()` 也从该 fd 读事件；`cover.c:same_node()` 用 `st_rdev` 判断，避免重复打开。

**兜底**：与 2.1 完全相同（供电、取消标记、显示忙、8 秒重试、RTC 测试闹钟、短返回）。额外一条：`power.sh` 的 `case "${1:-}"` 只接受 `restore|native|suspend`，其它实参 `exit 64` —— 但 `power_worker_start()` 固定传 `suspend`，正常路径不会触发。

**触发条件与设置组合**

- 通道能力上报含 `"armPageTurn" w_bool(1)`（`host.c:242`）；旧版兼容层返回不支持会隐藏设置入口。
- **文档（交接文档第 9 节 / `docs/翻页动画AB测试流程.md`）说的组合**：普通「翻页动画」= 无动画 + 「水波纹翻页」= 开 + 确实发了 `armPageTurn`。三者缺一即无 `arm` 行，**属 Reeden 设置问题，不是适配层问题**。
- `userdata/turn-profile`（`run.sh:132-140`，读前 32 字节并去空白）取值：`stable` / `off` / `timed` / `reagl` / `clean` / `sweep`。其中 **`off` 直接令 `animate=false`**（`display.c`），此时即使 `accepted=1` 也不会有 `bands=` —— 这是判读时最容易误判的一点。
- 彩色页、清屏、`inversion_change`（夜间全局反转切换）、`xres<160` 都会跳过动画走普通刷新路径（源码明确「Color pages and explicit cleans never use the animation sweep」）。

  - `(864,390)-(928,454)` 右上角关闭 / `(538,871)-(916,947)`「返回阅读」→ `shown=false`（**不发 action、无日志**）。

- **返回阅读不盖旧截图**：`system_panel_compose/redraw` 用 `copy_base()` 保存/恢复底图，退出面板时 `system_panel_redraw` 把 `base` 拷回并 `painted=false`；release 明确「退出面板恢复最新阅读画面，不把旧截图盖回页面」。此项**无日志**，只能肉眼验收。

## 4. 三个验收入口 + 亮度交接 + 隔夜功耗（源码依据）

### 入口 1：`[launcher] first frame took`（`scripts/run.sh`）
`exec >> "$APP/logs/launcher.log" 2>&1`（`run.sh:17` 之后）。首帧循环最多 20 次 × 1 s；成功时打印 `[launcher] first frame ready; hardware handoff authorized`（:166）+ `[launcher] first frame took Ns`（:167，N = `$(date +%s) - STARTED_AT`）。超时反证 `[launcher] no first frame in 20s; Nickel was never paused`（:151，`exit 20`）。校验缓存命中时打印 `[verify] manifest unchanged and every file present; skipped full hashing`（:85）——**这一行在 `launcher.log`，不在 `install-verification.log`**；`install-verification.log` 由 `run.sh:58`（`integrity.sh repair`）、`:61` / `:70`（`sha256sum -c SHA256SUMS`）三处重定向生成，内容是 `xxx: OK` / `FAILED` / `[INTEGRITY] ...`，位于 **APP 根目录**。**`PASS: all shipped file hashes` 不在此文件**，它来自电脑端 CI 自检脚本 `scripts/verify.sh:7`（`run.sh` 从不调用 `verify.sh`）。

### 入口 2：`FrontLightLevel` 交接（`scripts/recover.sh:sync_nickel_light()`）
- 配置路径：`cfg=${NICKEL_CONF:-/mnt/onboard/.kobo/Kobo/Kobo eReader.conf}` → USB 挂载后是 **`E:\.kobo\Kobo\Kobo eReader.conf`**（**不在 `.adds\reeden-kobo` 下**）。
- 只在 `[PowerOptions]` 段内读/写 `FrontLightLevel` 与 `FrontLightState`（awk：`/^\[PowerOptions\]/{po=1;next} /^\[/{po=0} po&&/^FrontLightLevel[ \t]*=/...`）。
- 触发条件（全部满足才写）：`state/native-restart` 存在且 `!pidof nickel`（真正退出回原生）；`clean_exit=true`；`choice_light` 有效 `<=100` 且 `>0`；`cfg` 存在且非符号链接；`level=$(cat /sys/class/backlight/mxc_msp430.0/brightness)` 在 1..100 且 **`level == choice_light`**；现有值不等于 `level`。
- `clean-exit` 由 `host.c:record_clean_exit()` 在 `user_exit && acquired && !sleeping && !terminating && !screen.failures` 时写入 `REEDEN_CHOICES/state/clean-exit`（内容 `pid brightness warmth wifi`）。**异常退出（崩溃、强制退出）不写，会恢复启动快照 —— 设计行为**。
- 日志（**都追加到 `launcher.log`**）：`[recovery] Nickel brightness updated to $level`（:90）/ `[recovery] Nickel brightness update failed; hardware value kept`（:93）。**没有独立的 recovery 日志文件**。
- 色温**不写**原生配置（release 明确）。
- **刻度说明**：交接文档称「Reeden 用感知刻度 11，sysfs/Nickel 用硬件刻度 46，数字不同正常，只要观感一致」。源码里 `host.c` 的 `setBrightness` 是把 `v.integer`（0..100）直写 sysfs，`recover.sh` 写入 `FrontLightLevel` 的也是同一个 sysfs 读数 `level`；**`.4` 源码中未见显式的 11↔46 换算实现**。因此本验收包的判读规则是：**只提取原始行、不做数值换算、以「观感一致」为准**（与交接文档结论一致），但把「映射未在源码中显式出现」列为疑点（见第 7 章）。

### 入口 3：`[power] invoked arg=suspend`（`scripts/power.sh`）
`exec >> "$APP/logs/power.log" 2>&1`（:5）后第一行即 `echo "[power] invoked arg=${1:-} $(date)"`（:7）。实参由 `power_worker.c` 固定为 `suspend`（休眠）/ `restore`（恢复 Wi-Fi）/ `native`（退出交接）。**只有 `=suspend` 是休眠尝试**。

### 补充：隔夜功耗取证（`scripts/standby_report.py`，电脑端只读，Python 3.10+）
- `log_report(power.log)`：`PHASE = ^\[power\] phase=(\w+) uptime=(\d{1,18}) pid=(\d{1,10})`，按 **pid 配对** `preparing` / `suspended` / `resuming`；`[power] entering mem ` 标记 `requested`；`^\[power\] mem returned=(\d{1,3})` 取结果；`[power] sample=(before_mem|after_mem) battery=<...> external=<...> capacity=(\d{1,3})` 取电量。
- `cover_report(previous.log / current.log)`：识别 `[cover] candidate eventN (SW_LID|internal KEY_F1)`、`[cover] no supported internal lid input; power key remains available`、`[cover] disabled by user preference` / `[cover] extra listener disabled; existing power handling unchanged`（**兼容旧日志**）、以及 `\[power\] phase=cover-(closed|opened) wall=(\d{1,10}) mono_ms=\d+`，用 `datetime.fromtimestamp(..., timezone.utc).astimezone()` 换算成时间。
- 还会检查 `state/power-screen-only`（只锁屏模式）与 `state/power-test`（测试唤醒闹钟）标记。
- 只读末尾 512 KiB、最近 3 次尝试；结尾明确输出「以上是脚本尝试记录，不是最低功耗驻留时间或耗电量」。
- **两种 `[power] phase=` 格式不能混用**：`power.sh:13` 是 `phase=$1 uptime=N pid=N <date>`（→ `power.log`）；`host.c:116` 是 `phase=%s wall=<UTC epoch秒> mono_ms=<ms>`（→ `current.log`）。`standby_report.py` 分别用 `recent_attempts()` 与 `cover_report()` 处理。

## 6. 静态层面能预判的失败点

1. **时区偏移按现场确认**：`power.sh` 用 `$(date)`（非 `date -u`），`run.sh` 未设 `TZ`，`git grep -E TZ=|date -u|UTC 3b804d2 -- scripts/` 零命中——**UTC 是 Kobo 默认时区的假设，不是源码保证**。日志通常比北京时间早 8 小时，但实机应先核对设备 `date` 输出；`host.c` 的 `wall=<epoch>`（`CLOCK_REALTIME`）可作绝对锚点。按错误偏移搜日志会误判「没触发」。判读脚本不做时间判定。
2. **`current.log` 轮转**：`run.sh:96` 每次启动 `mv -f current.log previous.log` 后重建；取证前多启动一次 Reeden，本轮合盖/水波纹日志就跑到 `previous.log`。脚本判读时合并 `previous.log`。
3. **`power.log` 轮转**：`run.sh:9-14` 超过 256 KiB 时 `mv -f power.log power.log.1`；隔夜长测后只采集主文件会漏证据。
4. **`accepted=1` 被误当成水波纹成功**：必须再看 `[page-turn] bands=`；`turn-profile=off`、彩色页、清屏、夜间反转切换都会令 `animate=false`，此时有 `arm accepted=1` 但无 `bands=` 属预期。
5. **供电保护被误判为故障**：USB 充电 / `battery=Full` / `external=on` → `[power] screen-only: supply guard ...` + `exit 3`，**只有 `invoked arg=suspend`、没有 `entering mem`**，是设计行为。脚本判 `NEED-EVIDENCE` 而非 `FAIL`。
6. **`invoked arg=restore` / `=native` 被误认成休眠尝试**：只有 `=suspend` 算。
7. **`mem returned=0` 且相隔数小时 ≠ 真低功耗**：release 明确本版尚未完成隔夜功耗验收，日志只证明脚本发起过请求。
8. **找不到 `[recovery]` 日志**：所有 `[recovery]` 行都在 `launcher.log`，设备盘上没有 `recovery.log`。
9. **`FrontLightLevel` 路径易错**：在 `E:\.kobo\Kobo\Kobo eReader.conf`，不在 `.adds` 下；异常退出/未调亮度时不写属设计行为。
10. **`no-sleep-cover` 被脚本自动创建**：这是**人工手动**回退步骤，脚本自动创建会污染验收并让 1.2~1.5 全部失效。
11. **`wifi-handoff` 取值**：只有 `keep` 生效，其它任意值（含空）都按 `default` 处理（`wifi.sh:wifi_handoff_mode`）。
12. **顶部下滑手势**：必须落在 `(300,0)-(772,24)` 且 `dy>=100 && dy>dx+40`；从边缘/斜向划不会展开面板，容易误判「功能没做」。
13. **面板 Wi-Fi 开关无响应**：`network==PANEL_UNKNOWN` 或 `busy=true`（处理中）时点击被忽略；首次展开会先发一次 `PANEL_PROBE`。
14. **`standby_report.py` 的两条旧日志字符串在 `.4` 不再产生**：用它判 `.4` 日志会一直显示「无记录」，见差异表 #9 / #10。
15. **两种 `[power] phase=` 格式混用**：`uptime/pid`（power.log）与 `wall/mono_ms`（current.log）不能互相配对；`standby_report.py` 也是分开处理的。
16. **缺少 NickelDBus**：返回原生后 Wi-Fi 选择记「未同步」，是 release 已声明的已知限制，不是缺陷；本包不安装任何插件。
17. **色温不写 `Kobo eReader.conf`**：只同步亮度，色温不变属预期。
18. **11 ↔ 46 感知/硬件刻度映射**：`.4` 源码中未见显式实现（见第 7 章疑点），脚本不做数值换算，只以观感一致判读。
19. **`install-verification.log` 位置**：APP 根目录，不在 `logs/`；去 `logs/` 找会落空。
20. **`standby_report.py` 依赖 Python 3.10+**（用了 `int | None`、`dataclass`、`:=`、`Path.is_relative_to`），且只取末尾 512 KiB / 最近 3 次尝试；本验收包**不依赖它**，纯 PowerShell 即可。
21. **`state/power-screen-only` / `state/power-test` 标记**：`host.c:513` 与 `power.sh:127` 会读它们，前者存在时根本不启动 `power.sh`，后者会设 30 秒 RTC 唤醒；release 未提这两个标记，取证时值得一并记录（脚本已在 manifest 中只读记录存在性）。

## 7. 疑点与边界（未在正文判读规则中假设）

- **`11 → 46` 刻度映射**：交接文档给出的这组具体数字，在 `.4` 的 `host.c` / `recover.sh` 中未找到显式换算代码；`setBrightness` 直写 0..100 的 sysfs 值，`FrontLightLevel` 写入的也是同一 sysfs 读数。**本报告不据此否定交接文档**（可能来自闭源 Reeden UI 的显示刻度），但建议实机同时记录 UI 显示值与 `FrontLightLevel` 实际值，作为额外证据。
- **`.4` 未做真机验收**：以上全部是静态代码路径推断，任何 `PASS` 都只代表「日志标记与源码一致」，不代表物理墨水屏观感、真实低功耗或闭源规则引擎已验证。
- **CI 全绿 ≠ 实机通过**：`ci.yml` 已无 `continue-on-error`，但自动化检查是合成输入/显示与脚本故障注入，不覆盖合盖磁铁、电池放电曲线、原生 Nickel 交接。
- **设备日志现在读不到**：`E:\` 未挂载，本报告无任何运行时采样；`Collect-Evidence.ps1` 已按「设备不在 → 明确提示、退出码 0」实现。

## 10. `.5` 增量代码路径（相对 `.4`）

> 依据 `git show 8fdd886:<path>`。`.5` 是 merge commit（父 `170364d` + `7275ea1`），本节只写**相对 `.4` 有行为变化**的部分；未列出的路径与第 1~9 章一致。

### 10.1 合盖：启动状态不再被当成边沿（`cover_seed`）

**文件 / 函数链**

```
scripts/run.sh -> src/host.c main() -> src/cover.c : cover_open()
  -> 若找到受支持节点：cover_seed(c)        （.5 新增，替代原来的 resync(c,0)）
       resync(c,0);  c->reported = c->observed;  c->due = 0;
  -> 主循环 cover_settled() 只有在 reported != observed 时才产生边沿
```

| 项 | `.4` | `.5` |
| --- | --- | --- |
| 合着盖启动 Reeden | 首次 poll 会把「盖子关着」当成一次 `COVER_CLOSED` 边沿 → 立刻锁屏/休眠 | `cover_seed()` 把观测值直接 adopt 成「已上报」并清掉去抖定时器 → **不产生边沿**，也不锁屏 |
| 之后真实合盖/开盖 | 正常 | 正常（`reported != observed` 才触发） |
| 验收影响 | — | **1.2 必须在开盖状态下启动 Reeden，再合盖**；合着盖启动看不到 `[cover] closed` 是设计，不是缺陷 |

### 10.2 锁屏图失败不再取消休眠

`host.c:498-506`：`display_cover()` 返回 <0 时只打印
`[sleep-cover] image not confirmed; keeping current page, continuing to suspend`，
**不再** `set_sleep(false)` 回阅读，而是继续往下走 `display_wait()` → 关背光 → 启动 helper。
`display_wait()` 失败仍 `app_quit=1` 走错误恢复（保留原设计）。验收含义：**这一行是设计行为，判 PASS 侧的解释，不是故障**。

### 10.3 彩色水波纹 CFA 路径（实验，默认关闭）

**开关链**

```
userdata/turn-profile 内容 = color
  -> scripts/run.sh:139   export REEDEN_TURN_PROFILE=stable REEDEN_COLOR_TURN=cfa
  -> src/turn_timing.c:29 REEDEN_COLOR_TURN 必须严格等于 "cfa"（其它非 "off" 值 -> invalid）
  -> src/display.c:322    color_animate 条件全部成立才走彩色路径
```

**`color_animate` 全部前置条件（`display.c:322-325`）**：`semantic_turn`（来自 `armPageTurn`）+ `turn_options.color_bands` + `profile != TURN_OFF` + **非清屏** + **非夜间反转切换** + `plan.color || plan.frame_color`（该页确实有彩色内容）+ 分辨率**必须 1072×1448 / rotate=3** + `xoffset==yoffset==0`。任一不满足即回落到灰阶/普通彩色路径。

**执行与日志（`display.c:202-224`）**

- `color_turn_bands()`：`steps = page_turn_steps`，**上限硬截到 8**；每段用 `refresh_color_band()`（`refresh_policy.c:56`，`aligned_band(..., 48)`，48 是 16px 更新对齐与 3px CFA 单元的公约数）；波形 `REFRESH_GLRC16`、`mode=1`、`flags=REFRESH_CFA_G2`。
- 提交用 `submit_sequence(..., max_inflight=1)`：**逐段串行**（一次只允许一个在飞行），因此彩色路径比灰阶慢。
- 成功：`[color-turn] bands=%u direction=%s vertical=%u path=cfa wave=%u mode=1; optical quality unverified`（`display.c:221`）。
- 失败：`d->turn_options.color_bands=false` + `[color-turn] incomplete; experimental color sweep disabled for this session`（`display.c:217`），**本次运行**回退普通彩色刷新（`plan.waveform=REFRESH_GLRC16`、`plan.flags=REFRESH_CFA_G2`，不回灰阶）。
- 另有夜间彩色分区日志 `[night-color] regions=%u cfa_rows=%u/%u`（`display.c:236`，`night_color_parts()`），**19 项判读不使用它**，仅作排错线索。

**判读边界**：`[color-turn] bands=` 结尾自带 `optical quality unverified`——**它只证明彩色事务串行提交完成，不证明彩字不淡化、不证明接缝/色偏可接受**。3.2 因此只做「有没有下发」的判读，观感必须人工对照。
