# 刷新与翻页动画开发记录

2026-11-02，尚未发布；不代表 GitHub v0.7.4 附件已包含这些改动。目标设备为 Clara Colour（393），固件 4.46.23836，当前实测官方核心为 Kindle 1.43.2+791。

## 夜间彩字

此前，一处彩字就会让整块正文使用 CFA 彩色刷新。灰阶与彩色画面切换还会改变全局硬件反相编码；编码转换需要重写全部像素，但不应因此额外请求清屏。仅取消这次额外清屏后，用户仍确认彩字页存在大面积闪烁，故不能将该步骤列为修复完成。

当前开发版在黑底阅读期间首次遇到彩色后保持直接 RGB 编码，避免每次彩字进入或离开时反复切换全局反相。普通翻页时，稀疏彩字按旧、新画面的彩色行共同划分：以 48 像素行组保留 CFA 相位和边界余量，彩字及旧色擦除使用 GLRC16 + CFA G2，其余行使用 GLKW16。每组提交使用同一张不可变最终画面；再次修改 framebuffer 前等待全部已接受的 marker 完成。

彩色覆盖超过半屏、分组过多、图片、显式清屏或主题明暗切换仍保留完整刷新路径，不承诺完全无闪烁。合成 ARM 回归覆盖颜色擦除、完整区域覆盖、分区波形及完成屏障；192×768 测例中 CFA 覆盖为 144 行。真实书页日志已记录 192/1448 行及 720/1448 行的 CFA 分区；用户确认“闪烁缩小，文字和颜色正常”。这只代表当前书页的实体对照，不等于所有书籍、图片或密集彩字都已验收。

## 翻页动画

复用官方原有“水波纹翻页”设置和语义指令。官方 Kindle runner 同样通过 `app.reeden.ireader_epdc` 提供 `isSupported`、`diagnostics` 和 `armPageTurn`；通道名称不代表 Kobo 使用 iReader 驱动。旧兼容层在该通道返回不支持，导致设置入口隐藏。当前开发版支持这条通道，读取官方 `forward`、`vertical`、`speedBits` 参数。

Kobo 后端使用分条提交实现扫动效果，未照搬 Kindle 私有 swipe ioctl。前后方向、纵向及速度档位由原设置控制；普通“翻页动画”需设为“无动画”。只有有效指令之后的灰阶正文大幅变化才使用扫动；彩色页面、锁屏和清屏保留普通路径。提交失败时先等待已经接受的更新完成，再用普通刷新补齐整页；过期指令不会触发后续页面动画。

首轮实体测试中，入口已出现，日志也记录分条执行，但用户看不到扫动，不能据此列为成功。加入 35 毫秒间隔后，真实设备的十条提交跨度约 335～346 毫秒；用户确认“可以扫动，但是太慢”。随后降低等待，用户仍反馈与 Kindle 差距较大、像大块画面在翻动，故未达到动画体验目标。

当前试验版进一步细分：快档十六段/6 毫秒、普通档二十四段/8 毫秒、慢档三十二段/10 毫秒。普通档在 1072 像素屏幕上的条带按 16 像素对齐，实际宽度为 32 或 48 像素，取代之前约百像素的宽条。分段数量增加后的前后方向、完整区域覆盖、完成屏障与提交错误回退已通过 ARM 隔离测试。这些是提交间隔，不等于整次翻页耗时；内核处理与面板完成还需时间。夜间彩字分区不额外延迟，全部显示完成屏障仍保留。

这仍然是 Kobo 的分区扫动模拟，不是 Kindle 专用硬件水波纹接口的原样移植。用户随后确认“更连续了，效果和速度可以接受”。对应设备日志是快档十六段、白底灰阶页，八次前翻和两次后翻均完成，无显示提交或完成错误；条带提交跨度约 147～179 毫秒，不代表完整翻页耗时。推荐当前机型先使用快档。普通档二十四段和慢档三十二段已做隔离测试，尚未分别取得实体效果反馈；夜间动画也未另行做这轮实体复测。
