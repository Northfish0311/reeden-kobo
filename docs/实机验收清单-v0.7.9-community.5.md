## 5. 本轮新增实现的取证判据（照抄日志原文，不要转述）

| 日志行 | 含义 | 判定 |
| --- | --- | --- |
| `[power] exclusive power key acquired (event2 name=…)` | 仅 main：`event2` 验证通过，直接独占 | 正常，未走扫描 |
| `[power] exclusive power key acquired (eventN scanned name=…)` | 仅 main：扫描选中其他节点 | 正常，记录 N；与 2A 枚举一致 |
| `[power] event2 does not report KEY_POWER; scanning /dev/input` | 仅 main：能力查询未确认 `KEY_POWER` | 需核对后续选中结果，不据此认定按键已正常 |
| `[power] event2 unavailable (…); scanning /dev/input` | 仅 main：打开 `event2` 失败 | 需核对后续选中结果 |
| `[power] exclusive power key acquired (event2 fallback, no candidate reported KEY_POWER name=…)` | 仅 main：未找到已验证候选，沿用旧路径 | 未确认电源键能力，见 B-12 |
| `[power] eventN rejected: no KEY_POWER, external bus, or the touch panel` | 仅 main：候选未通过过滤 | 正常诊断信息 |
| `[power] SYN_DROPPED; waiting for SYN_REPORT` | 仅 main：进入丢事件恢复，暂不接受按键 | 此行不表示恢复完成 |
| `[power] key state resynced at SYN_REPORT down=0/1` | 仅 main：已在报告边界重新查询真实状态 | 不是实机通过结论；还要检查后续单击及无多余锁屏 |
| `[power] key state resync failed: …; waiting for next SYN_REPORT` | 仅 main：查询失败，继续隔离不可信事件 | 不得出现伪造按键释放；等待后续重试成功 |
| `[color-turn] bands=N direction=… vertical=… path=cfa wave=11 mode=1; optical quality unverified` | 彩色条带序列完成 | N ≤ 8；每次翻页一组 |
| `[color-turn] incomplete; experimental color sweep disabled for this session` | 序列中途失败，本次运行关闭实验 | 页面必须仍是**彩色**，不得转灰 |
| `[color-turn] band i/N rejected; experimental colour sweep disabled for this session` | 仅 main：几何不满足条带条件，放弃该轮 | 后续页仍为普通刷新，且不再重复尝试实验 |
| `[sleep-cover] not registered; keeping current page` | 未注册封面图 | 正常，随后仍须 `entering mem` |
| `[sleep-cover] image not confirmed; keeping current page, continuing to suspend` | 可选封面图失败 | 解码失败可继续锁屏；硬件完成状态未知时必须走错误恢复，不能强求 `entering mem` |
| `[cover] closed` / `[cover] opened` | 盖子边沿 | 合盖开机时**不应**在启动阶段出现 `closed` |

## 6. 深睡有效判据（沿用 `.4` 第 4 节四联，不得放宽）

四联同时满足才算深睡：`entering mem` **且** `mem returned=0` **且** `phase=suspended`→`phase=resuming` 的 uptime 差 **>5s** **且** 该样本无 `screen-only` 且 `helper exiting=0`。

- 电脑侧判定统一用 `tools/Check-SuspendGate.ps1`（入口行只计数不计分）。
- 插 USB 或 `screen-only` 样本，一律记「不适用」，**不算失败也不算通过**。

| B-12 | 仅 main：未找到已验证电源节点时的兼容性 | 未证实电源键可用，相关用例记阻塞；回退节点打开或独占失败时应用会退出，不能把诊断脚本的候选行当作启动或按键成功。 |

## 11. CI 结果怎么读（新增，避免把环境问题当回归）

发版要求**所有必需测试 job 均为 `success`**，并确认发布 job 实际成功、附件存在且校验一致。没有 `failure` 不等于通过；`queued` / `cancelled` / 必需测试被 `skipped` 都表示尚未完成验证：

| 现象 | 含义 | 处置 |
| --- | --- | --- |
| 某 job `failure`，有失败 step | 真实门禁未通过 | **禁止发版**，修代码 |
| 某 job `cancelled`，**零 step 执行** | 排队超时/runner 取消，非测试失败 | 重跑该 job；门禁不放宽 |
| run 结论 `failure` 但全部 job 都是 success/skipped/cancelled | 由上一条 cancelled 连带 | 同上 |

- `usb-tools` 矩阵已设 `fail-fast: false`，同矩阵其他 job 失败不会自动取消它。`cancelled` 还可能来自用户手动取消、平台故障或同 ref 的新 push；必须看实际原因。tag run 不会被本项目的并发规则自动取消，但不能保证不受平台或人工中断影响。
- 一条腿被 cancelled ⇒ 整条 run 记 failure ⇒ `release` job 因 `needs` 不满足被**跳过**，tag 会存在但**没有附件**。所以 tag push 后务必确认 `release` job 实际执行过，而不是想当然。
- 历史实例：`7275ea1` 的 Windows、`205a25f` 的 macOS 曾在排队时取消，没有执行测试。这不是已发现代码回归，也不是测试通过。`.5` 标签 `8fdd886` 的成功记录只证明该提交的自动测试，不能替代 `205a25f` 或更晚改动的检查。
