## 5. 本轮新增实现的取证判据（照抄日志原文，不要转述）

| 日志行 | 含义 | 判定 |
| --- | --- | --- |
| `[power] exclusive power key acquired (event2 name=…)` | `event2` 验证通过，直接独占 | 正常，未走扫描 |
| `[power] exclusive power key acquired (eventN scanned name=…)` | 扫描选中其他节点 | 正常，记录 N；与 2A 枚举一致 |
| `[power] event2 does not report KEY_POWER; scanning /dev/input` | `event2` 存在但无 `KEY_POWER` | 正常（说明旧版在此固件上电源键本来就无效） |
| `[power] event2 unavailable (…); scanning /dev/input` | `event2` 不存在 | 正常（旧版此处会直接退出） |
| `[power] event2 fallback, no candidate reported KEY_POWER` | 全都没找到，回退旧行为 | **异常态**，电源键不可用，见 B-12 |
| `[power] eventN rejected: no KEY_POWER, external bus, or the touch panel` | 候选被能力/总线/触摸面板过滤 | 正常诊断信息，USB 键盘应出现在这里 |
| `[power] SYN_DROPPED; resynced key state down=0/1` | 内核丢事件后已按真实按键位图重同步 | 出现即已修复；重点看**其后单击是否一次生效** |
| `[color-turn] bands=N direction=… vertical=… path=cfa wave=11 mode=1; optical quality unverified` | 彩色条带序列完成 | N ≤ 8；每次翻页一组 |
| `[color-turn] incomplete; experimental color sweep disabled for this session` | 序列中途失败，本次运行关闭实验 | 页面必须仍是**彩色**，不得转灰 |
| `[color-turn] band i/N rejected; experimental colour sweep disabled for this session` | 几何不满足 48px 对齐，放弃该轮 | 后续页仍为整页彩色，且不再重复刷屏 |
| `[sleep-cover] not registered; keeping current page` | 未注册封面图 | 正常，随后仍须 `entering mem` |
| `[sleep-cover] image not confirmed; keeping current page, continuing to suspend` | 封面图渲染未确认 | 正常；**不得**出现亮屏回到阅读，随后仍须 `entering mem` |
| `[cover] closed` / `[cover] opened` | 盖子边沿 | 合盖开机时**不应**在启动阶段出现 `closed` |

## 11. CI 结果怎么读（新增，避免把环境问题当回归）

判 release 能否发，只看「有没有 conclusion = **failure** 的 job」，不看整条 run 的红绿：

| 现象 | 含义 | 处置 |
| --- | --- | --- |
| 某 job `failure`，有失败 step | 真实门禁未通过 | **禁止发版**，修代码 |
| 某 job `cancelled`，**零 step 执行** | 排队超时/runner 取消，非测试失败 | 重跑该 job；门禁不放宽 |
| run 结论 `failure` 但全部 job 都是 success/skipped/cancelled | 由上一条 cancelled 连带 | 同上 |

- `usb-tools` 矩阵已设 `fail-fast: false`，腿之间**不会**互相取消；出现 cancelled 只可能是「被同 ref 的新 push 顶掉」或 runner 排队超时。**tag run 不受并发取消影响**，发版不会被执行到一半。
- 一条腿被 cancelled ⇒ 整条 run 记 failure ⇒ `release` job 因 `needs` 不满足被**跳过**，tag 会存在但**没有附件**。所以 tag push 后务必确认 `release` job 实际执行过，而不是想当然。
- 已发生的实例：`main` 上 `7275ea1`（2026-11-12 15:09 北京时间）被取消的是 `windows-latest`，`205a25f`（22:03）被取消的是 `macos-15`，都是排队阶段零 step 执行；内容相同的 tag run（`8fdd886`）全绿。**不要把这类红当成代码回归。**
