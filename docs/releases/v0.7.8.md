# Reeden Kobo v0.7.8 (Experimental)

针对用户反馈的“安装后 6/480 文件校验失败、无法启动”，加入资源恢复与完整性诊断。日志确认三种资源在官方资源目录和 UI 资源目录各缺一份；本轮原样 v0.7.7 全新实机安装没有复现自行丢失，故不将第三方环境的唯一根因宣称为已查明。

## 本版改动

- 电脑组包时生成本地资源恢复归档，并将归档列入安装 SHA 清单。官方核心及该归档不随公开适配器附件分发，来源仍是用户取得并校验的官方包。
- 每次启动重新验证安装，不因历史 `install-verified` 标记跳过。缺失的 `core/data/` 或 `ui-assets/` 文件可从已校验归档逐项恢复，再核对原 SHA；最后仍执行全量校验。
- 现存文件内容变化、恢复归档损坏、程序文件缺失均继续拒绝启动；不覆盖用户书库、笔记和设置，不重写 SHA 清单。
- 自检显示实际安装版本并列出具体失败文件，修复旧标题固定显示 0.7.2 和错误仅显示末三行的问题。
- 安装完成前增加可用平台的写入同步；USB 仍需安全弹出。

## 验证与范围

本地全部 17 个 Python 回归文件通过，其中新增 17 项资源恢复故障回归；已用真实官方 791 包验证组包及报告中六资源的删除/恢复路径。发行 CI 继续执行三平台安装卸载、Python 双版本、ARMHF 重建、预编译件逐字节比对、C 回归及 QEMU。

实机验证（产品代码 393 / 固件 4.46.23836）：先删除旧安装和测试备份，用原样 GitHub v0.7.7 全新安装，480 项校验、首帧和退出通过；再全新安装 v0.7.8 候选，在设备上精确删除反馈中的六处资源，确认出现 6/484 缺失失败。启动新版后六个文件全部自动恢复，原 SHA 清单摘要保持不变，484 项完整性检查通过，显示/触摸首帧交接成功。临时维护端口已清理，常规诊断入口恢复。反馈用户的 4.42.23291 固件未在本轮设备上重测，不能推断已覆盖。

支持范围仍为 Kobo Clara Colour（产品代码 393），已测固件 4.46.23836，电脑需 Python 3.10+，设备需 NickelMenu。官方 Kindle 核心白名单仍为 1.43.2+791 / 1.43.1+780；780 的完整资源来源校验限制不变。翻页动画与淡残影状态沿用 v0.7.5，本次未修改显示生产代码或宣称残影已经解决。

详细见[资源缺失排查与恢复](https://github.com/SSNQ/reeden-kobo/blob/v0.7.8/docs/资源缺失排查与恢复-20261105.md)。已有安装先退出 Reeden，使用安装器的保留数据升级方式。
