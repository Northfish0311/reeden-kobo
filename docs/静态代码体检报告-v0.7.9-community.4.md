## 1. 各成员核心结论

### 🔍 产品评审员（代码审查，以收口版为准）
核心判断：**🟡 有条件具备发 prerelease 让人拿真机验的条件，🔴 阻断项 0 条**。项目铁律全部通过；无数据损坏 / 变砖 / 无法回退风险；失败均有日志；有 `userdata/no-sleep-cover` 关闭开关与只读 `standby_report.py` 辅助定位；release 固定 `prerelease:true` 且 README / release notes 诚实标注未实机验收——这正是 prerelease 的用途。条件是 2 个 🟠 高优先项（各 1–3 行）建议发版前修：`cover.c:70` 的 `resync(c,0)` 让「启动即合盖」绕过 150ms 去抖立即产生 `COVER_CLOSED`；`host.c:498-502` 封面图失败会 `set_sleep(false)` 主动唤醒并清零 `suspend_at`，导致本轮锁屏彻底不再尝试休眠。两者都命中头号卖点「合盖休眠」，一个让它误触发、一个让它看起来完全没生效。**收口版主动剔除了上一稿中静态不可证伪的推测项**（event2 硬编码、面板尺寸解耦、CI 组合未修复当缺陷、`close()` 循环性能），并纠正一处事实错误：封面图失败时 helper 尚未启动，**不会**连带 `finish_power` 恢复 Wi-Fi。

### 🔧 排障手（健康检查与根因推断）
核心判断：**🔴 历史根因完全没有被修复，只是被绕过**。对比 diff 可见 `host.c:465/466/555` 全是上下文行，电源键仍固定单一 event2 + 单一 KEY_POWER，没有能力发现、没有 SYN_DROPPED 重同步；讽刺的是 .4 新增的 `cover.c` 已经会扫 `event0..31`、会处理重同步，但这套能力只用于翻盖传感器，没有应用到电源键。合盖或点面板后日志**会**出现 `invoked arg=suspend`，但那不经过 KEY_POWER；而 `power.sh:7` 甚至在所有 guard 之前就打印，插 USB 时 `:89` 必然 `exit 3`。最可能验不过的是合盖链路——`source_type()` 的设备名/事件码白名单是对一块从未 evtest 确认过的硬件做的猜测；最容易被误判为通过的是休眠链路。另发现 `state/power-screen-only` 全仓只读不写、不在任何清理清单，一旦手工放过即跨会话永久静默禁用全部休眠。

### ✅ 质量门神（QA 与发布）
核心判断：**🟡 条件 Go 维持现状 / 🔴 No-Go 转正式**。CI 与产物一致性侧已经干净且门禁真实（`continue-on-error` 全树 0 命中、11/11 哈希对得上、`verify` 的 `cmp` 会拦住不一致、release job `needs` 完整），但 macOS 15 + Python 3.10 只是「不再绕过」而非「根因定位」，改的是矩阵拓扑。真正卡发布的是：真机覆盖 0、`host.c` 主循环 173 行改动零可执行覆盖（CI 只编译不运行）、5 条新功能全部直接操作硬件、固件错配。另给出 9 项 A1–A9 真机验收检查表与完整回滚预案，并指出回滚被发布工程阻塞：community.1/.2/.3 缺 `docs/releases/<tag>.md`、`PORT_VERSION` 陈旧、文档硬编码版本号。
