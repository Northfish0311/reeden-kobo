# Reeden Kobo 使用与验收记录

适用：Kobo Clara Colour 393，固件 4.46.23836。官方核心白名单 1.43.1+780 / 1.43.2+791。仅适配当前机型，仍为实验版本。

社区修复版的变更和验证范围见 [v0.7.9-community.5 发布说明](releases/v0.7.9-community.5.md)；原作者的 v0.7.8 资源恢复测试见[上游记录](资源缺失排查与恢复-20261105.md)。以下按版本保留历史测试结果，不代表全部已经在当前版本复测，也不代表社区修复已完成实机验收。

## 0.7.8 社区整合验证

- 模拟 USB 升级中保留原菜单、书库、笔记和旧版备份，同时安装并校验新的资源恢复归档；归档不包含用户数据。
- 在支持 `os.sync` 的平台，保留菜单和替换默认菜单两条分支都执行写入同步。Windows 仍依赖用户安全弹出。
- 旧会话成功恢复后才校验、补回资源；恢复忙或失败时立即停止，不启动资源修复和硬件交接。
- 校验清单缺失、为空、是目录或符号链接时拒绝启动，不因历史校验成功标记放行。
- 沿用上游 17 项资源恢复故障回归，并保留社区的会话锁、充电锁屏和 Wi-Fi 恢复回归。

上述为自动化测试范围，结果以对应提交的 CI 为准。实机仍需测升级前后阅读数据、首启等待、锁屏/唤醒、返回主页联网；不在用户设备上主动删除资源进行破坏性验证。

macOS 的自动化环境固定为 GitHub 的 macOS 15 Apple Silicon 镜像，分别使用 Python 3.10 与 3.12；不能据此宣称其他 macOS 版本或真实 USB 设备已经通过。

## 耗电与原生设置

有用户报告运行时耗电偏高，Wi-Fi 和前光也没有沿用原生界面的所有设置。这是待复核的使用反馈，不是已经定位到的耗电原因；下文其他版本的续航记录不能代替本机测量。

- **耗电：** 在未插 USB、亮度和 Wi-Fi 状态相同的条件下，分别记录使用原生阅读器和 Reeden 的起止电量、时长。阅读与锁屏待机分开记录。USB 充电时程序有意不进入内核深睡，不能拿这个状态比较待机。若有 `logs/power.log`，核对同一时段是否尝试进入深睡、何时返回；日志不能给出实际耗电量。
- **Wi-Fi：** 从顶部中间下拉设备控制，分别测试关闭、开启、刷新和没有已存热点在附近时的状态。开关必须改变真实接口，未关联或没有 IP 不能显示“已连接”。成功的主动选择与休眠临时断网分开记录。返回原生系统时，如已有 NickelDBus，会请求同一开关状态并读取接口核对；缺少插件、请求失败或状态不符时记录未同步，不在原生界面下另起网络进程。回到主页后仍需检查开关、扫描和连接。不需要提供网络名称或密码。
- **亮度与色温：** community.4 在确认正常退出后保留本次用户明确调整的值；崩溃、锁屏或未调整时恢复启动快照。正常退出且用户明确选择非零亮度时，在 Nickel 启动前更新其原有配置中的亮度；不把临时灭灯写成新偏好，不改其他配置项或同步原生色温。原生系统后续仍可能根据自身策略调光，需实机检查。
- **合盖：** community.4 新增内部 `SW_LID` / 已知 Kobo `KEY_F1` 监听，识别成功后默认启用。保持 Reeden 打开，合盖应锁屏关灯、开盖应恢复；未知传感器显示暂不支持。分别检查电池供电、USB 充电和连续开合。灭屏不等于内核休眠，开盖唤醒和隔夜耗电仍需实机确认。
- **短暂唤醒：** 休眠很快返回时不自动亮屏；每次锁屏最多延迟 8 秒重试一次，重试仍会检查电池、显示空闲和用户唤醒请求。不循环重试，不设置日常唤醒闹钟，不改内核参数。供电状态不明或显示仍忙时保持锁屏并留日志。

**拔线后锁屏，隔夜仍掉电：** 无须重装阅读器或为了排查再等一晚。下次正常唤醒后连接电脑，在含有本工具的源码目录中运行 `python scripts/standby_report.py`。也可用 `python scripts/standby_report.py --log power.log` 检查已复制的日志。这个工具只在电脑上读取现有记录，不在 Kobo 上运行或采样，不修改书库、网络、系统配置或唤醒闹钟；原作者版已有相应日志也可以分析。

按照日志日期对照当晚：旧日志里的“充电”只说明脚本没有读到 `Discharging`，不能反推用户插了线。请求返回的间隔是两个阶段的时间差，不是实测的深睡时长；没有记录也不能证明一直醒着。当前存在的只锁屏或测试闹钟标记单独列出，不能当作隔夜状态。如果能从原生主页再作自然使用对照，应保持前光和 Wi-Fi 条件一致。

规则卡死与翻页残影另行排查。先保存现有 `logs/launcher.log`、`logs/current.log` 或 `logs/previous.log`，再做单项对照，不要求反复触发死机。原始日志、书页照片和阅读数据勿公开上传。

## 阅读器恢复与锁屏

- 恢复途中重启，不需手工删除 `state/active` 或 `state/recovering`。再次选择 **Reeden Kobo - Return Home**；如果确实有恢复进程正在工作，让它完成。
- USB 充电时只锁屏、不进入内核深睡，守护程序仍检测阅读器是否响应。真正的深睡不计入卡死超时。
- 返回 Kobo 主页后，如日志提示 `native Wi-Fi handoff pending`，表示主页已恢复但 Wi-Fi 交还未确认；可先在原生界面检查连接。下次返回主页前会再次尝试，不会在已运行的原生界面下擅自关闭无线。
- 已设置的锁屏封面未能确认刷上屏时，程序取消这次休眠，不把屏幕仍可能停在书页的情况记作成功。

以上覆盖模拟掉线、并发恢复、充电锁屏心跳和驱动拒绝刷新；模拟结果不能代替实际 Kobo 上的断电、休眠和屏幕验收。

## 一键安装与升级说明

1. 从 Reeden 官方取得 Kindle 版 `1.43.1+780` 或 `1.43.2+791` 安装包 (`Reeden-kindle.zip`)，放在本工具目录或系统「下载」文件夹。
2. **USB 数据线一键安装/升级（免 SSH）**：将已安装 NickelMenu 的 Kobo 连接电脑，双击 `一键安装-macOS.command` 或 `一键安装-Windows.bat`（或运行 `python3 install.py --usb [--upgrade]`）。
3. **SSH 无线一键安装/升级**：运行 `python3 install.py --ssh <Kobo_IP> --port 2222 [--upgrade]`。升级时会自动将旧版备份至 `.adds/reeden-kobo-backup-*`，并完整保留 `userdata/` 与 `storage/`。

## community.5：彩色水波纹实验

默认仍跳过彩色页的灰阶动画。community.5 增加独立、默认关闭的 CFA 条带路径；详见[彩色水波纹实验](彩色水波纹实验.md)。测试覆盖日夜彩字、背景图、旧色擦除、整帧 RGB 保留、两个方向和轴向、48 像素边界、最多一个在途彩色事务、失败/取消后的 CFA 回退和完成失败时不推进缓存。它不是“关闭彩色动画就算修好”的表述，也不是物理面板色彩或规则引擎稳定性的验收。

## 0.7.0 隔夜唤醒与彩色/灰阶刷新

隔夜日志显示 02:55 进入 mem、11:14 返回，之后未完成阅读器恢复。旧宿主只等待休眠 shell 的退出状态，运行时的全局 wait() 可以抢收这个子进程，导致持续等待。0.7 使用不执行 exec 的独立监督进程及专属等待类别，避免与 Dart 的回收线程竞争；等待错误直接返回原生界面。恢复检查先于引擎任务，任务队列每轮有时间预算。

新增 preparing / suspended / resuming / complete 阶段及时间记录。真实深度休眠期间守护程序继续放行；准备或恢复阶段超过 45 秒会恢复原生界面。网络恢复命令增加时限。历史记录当时尚待过夜实体复测。

**2026-11-03 用户反馈**：隔夜休眠问题已解决，续航实测可接受。本条来自用户实际使用反馈，本轮未进行设备测试或新增功耗测量；下文各版本的测试结果仍按原日期保留。文字残影尚未完全消除，Q（动画后整页复绘）继续保持撤回状态，详见[文字下缘横向拖影诊断](文字下缘横向拖影诊断-20261102.md)。

刷新对照 KOReader MTK：灰阶日间 GLR16/GC16、灰阶夜间 GLKW16/GCK16、真实彩色及旧色擦除 GLRC16/GCC16 + CFA G2；保留完整灰阶，不额外进行二值化或硬件抖动。RGB 通道差不超过 2 的舍入噪声不再触发彩色路径，单个真实彩色字仍会触发。

纯灰阶黑底补齐硬件反相：将 Dart 已渲染的黑底像素转成驱动所需的互补灰阶，使用 night_mode 4，RAM 中保持原始逻辑画面。真实彩色画面保留直接 CFA 路径，避免将后级灰阶反相错误当作 RGB 反相。切换硬件编码时重写完整画面，每次 FULL REAGL/CFA 请求等待刷新完成。锁屏封面、正常退出及异常恢复均还原硬件反相。

充电保护、恢复阶段超时守护、刷新策略已通过电脑端隔离测试；设备端合成测试及实体效果另行记录。

## 0.6.0 黑底刷新与全刷调度（历史版本）

黑底灰阶普通刷新使用 GLKW16（9），黑底清屏使用 GCK16（8）；白底保留 GLR16（4）/GC16（2），真实彩色内容保留 GLRC16（11）/GCC16（10）。依据实际画面背景识别，黑白切换清一次屏；不对已经渲染成黑底的图像再次反相。白色局部弹层单独判断。

取消适配层独立的十次大画面清屏计数，由 Reeden 自己的自动全刷设置及手动刷新控制。临近的全刷与待提交画面合并，500 毫秒内同一已清屏图像的重复请求合并。较长延迟的请求仍保留。KOReader 支持独立夜间全刷间隔；本次未给 Reeden 新增该设置。

真实黑底截图的离线识别、昼夜/彩色/局部弹层/边界及调度测试通过；用户随后反馈黑底大刷仍白闪，未通过实体效果验收。0.7 补充了完整的硬件反相与刷新完成同步。

## 0.5.0 冷暖光控制

在「书页中央 → 显示」的前光行下方增加「冷暖」行，支持冷/暖两端、加减和滑动。0 为最冷、100 为最暖，硬件实际分为 11 档。松手后保存至 userdata/kobo-light.conf；锁屏时保留，重启 Reeden 后恢复。只写冷暖混光接口，不改变亮度。

这是 Kobo 适配层对当前中文阅读面板的扩展，官方引擎和 AOT 保持原字节。识别限定为当前字体和 1072×1448 布局；识别不匹配时不插入、不接管触摸。硬件范围、触摸映射、持久化和启动保护已在电脑及设备隔离测试中通过。用户已确认实体冷暖、原有前光调节，以及关闭面板后的书页点击/翻页均正常。设备读回 warmth=40，对应混光接口原始值 6；亮度独立调节正常。实际重启后的冷暖恢复尚未另行做实体复测。

## 0.4.0 刷新与空闲优化

- 文字页按灰阶处理，彩色内容和旧彩色像素擦除使用彩色波形；保留主动全刷。
- 刷新区域增加边缘余量并按 16 像素对齐，减少边界残留。
- 在 RAM 中比较上一张已提交画面，跳过重复帧；短暂合并连续画面。清屏兜底按 10 次较大画面变化计算，不代表精确的 10 次翻页。
- 主循环按事件和任务期限等待，心跳移入 RAM，每 5 秒更新；不再每 50 毫秒固定唤醒或每 2 秒写存储心跳。
- 编译、纯算法测试、恢复及充电保护检查通过；用户确认残影减轻、翻页明显加快。AI 任务结束后的静止书页约 12 秒采样中，Reeden CPU 约 0.8%，画面未刷新。实际续航提升仍需更长时间比较。未改变全局 CPU 频率设置，也未强制关闭阅读期间的 Wi-Fi。

## 启动与使用

1. 回到 Kobo 原生主页并连接 Wi-Fi，在 NickelMenu 点「Reeden Kobo (test)」。不要从 KOReader 内启动。
2. 从书架打开书籍。官方文件选择器中的 `/mnt/us` 指向本应用的 `storage/`；测试书位于 `/mnt/us/documents/Kobo-port-test.epub`。
3. 在设置中开启「自定义锁屏画面」。电源键短按锁屏，再按唤醒，保留当前阅读进程与书页。
4. 深度休眠会临时关闭 Wi-Fi，SSH 随之断开，唤醒后会重新启动网络连接。充电时仅锁屏、关灯，按 MTK 机型限制跳过内核深度休眠。
5. 同时按住屏幕左右上角约两秒可退出，重新启动 Kobo 原生界面。电源键不再用于退出。
6. USB 连接或启动其他阅读器前先退出 Reeden。community.4 的保护盖路径仍属实验功能；若传感器不支持或开盖无法唤醒，先用电源键，不要反复触发。

## 恢复与日志

应用目录为 `/mnt/onboard/.adds/reeden-kobo/`。0.7.2 不再提供开启 SSH 的菜单，只提供停止旧监听的入口；可选密钥认证工具见 [SSH 说明](SSH.md)，无开机自启。设备休眠时无法通过 Wi-Fi SSH 连接。

SSH 恢复入口：`sh /mnt/onboard/.adds/reeden-kobo/recover.sh`。正常运行时会保留本次 native 环境白名单；退出会启动新的 Nickel 和看门狗，避免继续使用过期的暂停计时器。软件恢复不能保证处理所有内核故障。

- `logs/current.log`：本次 Flutter、显示、输入及生命周期。
- `logs/power.log`：屏幕空闲、休眠请求、返回结果及网络重启。
- `logs/launcher.log`：首帧、硬件交接与恢复。
- `logs/native.log`：返回原生系统的启动日志。
- `diagnostics/backups/before-030/`：本次电源适配前的程序及阅读数据备份。

官方引擎、AOT 和原始资源保持原字节；中文字体使用独立资源覆盖层。没有修改账号、授权或付费功能。公开分享应只分发适配层，官方核心由接收者自行取得。
