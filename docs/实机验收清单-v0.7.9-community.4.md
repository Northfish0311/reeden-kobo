## 2A. 接设备第一件事：枚举 `/dev/input/event*`（P0 前置卡点，先于升级和所有用例）

> **为什么必须先做**：`src/host.c:465` 把电源键**硬编码**为 `/dev/input/event2` 并 `EVIOCGRAB` 独占，抓不到就 `app_quit=1` 直接退出；`src/input.c:26` 触摸默认 `/dev/input/event1`（只有触摸能用 `REEDEN_TOUCH` 覆盖，**电源键没有覆盖入口**）。`src/cover.c:59-68` 虽会遍历 `event0~event31` 找 `SW_LID` 或 `gpio-keys`/`ntx_event0` 上的 `KEY_F1`，但会排除与触摸同一节点、并可能与电源键共享同一 fd。本机是 4.46.23852，仓库历史实机证据来自 4.46.23836——**event 编号一旦不同，C/D/F 组全部用例都会变成无效测试，甚至启动即退出**。所以接上设备的第一件事不是升级、不是备份，是枚举。

**设备侧只读命令**（不需要 evtest/getevent，Kobo busybox 即可）：

```sh
date -u
cat /proc/bus/input/devices
ls -l /dev/input/event*
cat /proc/bus/input/handlers 2>/dev/null
```

`/proc/bus/input/devices` 直接给出每个 event 的 `N: Name=`、`H: Handlers=eventN`、`B: EV/KEY/ABS/SW` 能力位图。

**怎么把结果取回电脑**（两种都在**拔线状态**下执行；USB 连接时设备处于 mass storage，NickelMenu 菜单通常点不了）：
- **A（推荐）**：先在 Nickel 主页用 NickelMenu 一次性 `cmd_output` 或包一段脚本，把输出写到 `/mnt/onboard/.adds/reeden-kobo/logs/input-enum.txt`；**然后再插 USB 点「连接」**，从 `E:\.adds\reeden-kobo\logs\input-enum.txt` 读取。用完删掉临时脚本与输出。
- **B（可选）**：`docs/SSH.md` 的诊断 SSH（默认关闭、需公钥 + KOReader dropbear、端口 2223）：`ssh -i <私钥> -p 2223 root@<Kobo_IP> 'cat /proc/bus/input/devices; ls -l /dev/input/event*'`，结束后务必执行 `reeden-ssh.sh stop`。

**记录表（C/D/F 组前置证据，必填）**

| event | `N: Name=` | Handlers | 关键能力（SW_LID / KEY_F1 / KEY_POWER / ABS_MT） | 与硬编码是否吻合 |
|---|---|---|---|---|

**判定与停手条件**：
- [ ] `event1` 是触摸（有 `ABS_MT_POSITION_X/Y`）→ 与 `input.c` 默认一致
- [ ] `event2` 是内部 GPIO 电源键（`gpio-keys` / `ntx_event0`）→ 与 `host.c:465` 一致
- [ ] 记录是否存在 `SW_LID` 设备及其 event 号，并与 `current.log` 的 `[cover] candidate eventN SW_LID|internal KEY_F1` 交叉核对（`standby_report.py` 也会解析这行）
- [ ] **若 event2 不是电源键 / 编号与硬编码不符 → 立即停手**：这是设备枚举与硬编码不匹配的前置条件失败，先修代码或确认 `REEDEN_TOUCH`，**不得把后续用例判成「适配层缺陷」，也不得判成「通过」**
- [ ] 枚举原始输出留存为附件，不公开上传（S11）


| 日志行 | 含义 |
|---|---|
| `[launcher] first frame took Ns` | 启动首帧耗时 |
| `[verify] ... skipped full hashing` | 校验缓存生效 |
| `[recovery] Nickel brightness updated to N` | 亮度写回 Nickel |
| `[page-turn] arm ... accepted=1` / `[page-turn] bands=…` | 翻页动画请求 / 分条动画落地 |
| `[power] invoked arg=suspend` | **仅脚本入口日志**（`scripts/power.sh:7` 无条件打印），**不作任何判据** |
| `[power] entering mem` / `mem returned=0` / `phase=suspended`→`phase=resuming` | 实际写 `/sys/power/state` 前 / 内核返回 / 阶段切换（**真判据**） |
| `[power] screen-only: supply guard ...` | 供电保护触发，**只锁屏不深睡**，该次样本无效 |
| `FrontLightLevel` | 退出后交接给 Nickel 的亮度 |

### ⚠️ 深睡有效判据（四联，替换所有以 `invoked arg=suspend` 为准的旧门禁）

**假阳性根因**：`scripts/power.sh:7` 一进脚本就 `echo "[power] invoked arg=${1:-} $(date)"`，只要宿主以 `suspend` 参数调用就必有这一行。而 `power.sh:89` 的 `on_battery prepare || exit 3` 在 USB 充电 / 非 `Discharging` / `external=on` 时会打印 `[power] screen-only: supply guard battery=... external=...` 后**直接 `exit 3`，根本没进内核深睡**。验收恰恰要靠插 USB 才能读 `E:\...\power.log`，于是旧门禁「`power.log` 出现 `invoked arg=suspend`」在插线场景下**必然 PASS 且是假阳性**。

**通过判据必须四条同时满足**（`TC-COVER-002` / `TC-POWER-001` / `TC-GUARD-001` / G-11 第三问 / 表 A 第三问统一适用）：

1. `[power] entering mem`（`power.sh:136`）；
2. `[power] mem returned=0`（`:142`）；
3. `phase=suspended` → `phase=resuming`，取这两行各自的 `uptime=` 相减，跨度 **> 5 秒**（`:146-152` 把 ≤5s 判为 `short mem return` 并 `exit 76`）；**注意不是 `preparing`→`resuming`**——那包含准备阶段，官方明确不能当实测深睡时长；
4. 全程**没有** `[power] screen-only: supply guard ...`、**没有** `helper exiting=3|4|75|76` 提前退出。

- [ ] 门禁自检：把 `power.log` 里所有 `invoked arg=suspend` 行逐条核对，**只有伴随 `entering mem` 且满足四联的才计入通过数**；仅有入口行的一律标「不适用 / 无效样本」
- [ ] **取证顺序铁律**：合盖 / 短按电源键必须在**拔掉 USB、电池供电**下执行并保持拔线直到唤醒；一轮结束后**先退出 Reeden 回 Nickel 主页**，再插 USB 读 `power.log`（日志追加写入，不会丢）。**插着 USB 的会话一律不得判 PASS，也不得判 FAIL**

**SHA256SUMS 逐文件校验（升级前后各一次，差异总数必须为 0）**

```powershell
$app = "E:\.adds\reeden-kobo"; $bad = 0
foreach($line in [IO.File]::ReadAllLines("$app\SHA256SUMS")){
  if($line -notmatch '^([0-9a-f]{64})  (.+)$'){ continue }
  $p = Join-Path $app ($Matches[2] -replace '/','\')
  if(-not (Test-Path $p)){ "缺: $($Matches[2])"; $bad++; continue }
  if((Get-FileHash $p -Algorithm SHA256).Hash.ToLower() -ne $Matches[1]){ "差: $($Matches[2])"; $bad++ }
}
"差异总数 = $bad"
```

## 9. 隔夜功耗的正确测量方法

> ⚠️ **两条否定式认知**：
> 1. **`invoked arg=suspend` 连「发出深睡请求」都证明不了**——它是 `power.sh:7` 的入口无条件打印；插 USB 时 `power.sh:89` 的供电守卫会 `exit 3` 只锁屏，日志里照样有这行（见第 4 节四联判据）。即便四联齐、`mem returned=0`，也**不等于真正进入低功耗**——可能被立即唤醒、`wifi-handoff=keep` 保持 Wi-Fi 供电、前光未灭、Flutter timer 仍在跑。
> 2. **相隔数小时看电量下降 ≠ 测得低功耗**：电量百分比是粗粒度查表估算，期间唤醒/充电/温度/起始电量不同都会污染；单独一个「一夜掉 5%」既不能证明失败也不能证明成功。

- [ ] 断开充电器与 USB；记录 `wifi-handoff` 取值并单独标注（`keep` 会抬高基线，与「不设」分开统计）
- [ ] 记录起始电量 %、起始时间（UTC + 北京时间双记）、环境温度、设备表面温度、版本、配置快照
- [ ] 合盖后静置 ≥8 小时（建议 22:00–06:00），全程不操作、不插线、不充电、不唤醒
- [ ] **必需对照组**：同起始电量、同环境、同时长下跑一次「原生 Nickel 待机（不进 Reeden）」
- [ ] 证据链：**第 4 节四联判据齐**且**无立即 resume**；间隔内 `current.log` **无新增** page-turn / touch / wifi 活动；暗室确认屏幕与前光熄灭；设备不发热
- [ ] 记录结束电量 %、结束时间、结束温度
- [ ] **连续 ≥2 晚取均值**；单次不下结论
- [ ] 无效样本（充电 / USB / 合盖未生效 / 用户唤醒 / 温度剧变）剔除并标注原因后重测
- [ ] 只出《隔夜功耗观测记录表》实测值与对照差值，**不判定合格、不纳入门禁**；明显高于对照组按 P2 记录并附证据

**日志判读陷阱（仓库 `docs/测试说明.md`）**：旧日志里的「充电」只说明脚本没读到 `Discharging`，**不能反推用户插了线**；请求返回的间隔是 preparing→resuming 两个阶段的时间差，**不是实测深睡时长**；没有记录也**不能证明设备一直醒着**；只锁屏或测试闹钟标记要单独列出，不能当作隔夜状态。USB 充电时程序有意不进入内核深睡，该状态**不能拿来比较待机**；日志本身**不能给出实际耗电量**。

## 10. 失败分级与回退（由轻到重）

| 级别 | 定义 | 是否阻塞 |
|---|---|---|
| P0 | 崩溃 / 数据丢失 / 文件系统损坏 / 无法交还 Nickel / 运行时拔线 / 擅自装插件 | **是**，立即中止 + 回退 + 上报 |
| P1 | 合盖不熄灭、面板不弹、**四联判据不齐**（`entering mem` / `mem returned=0` 缺失，或把 `screen-only` 误判为通过）、Wi-Fi 无效、首帧超时、亮度错乱、充电中误休眠 | **是**（除非书面豁免） |
| P2 | `accepted=1` 无动画、待机报告字段缺失、功耗明显偏高 | 否（需豁免） |
| P3 | 面板文案、「未同步」措辞 | 否 |

| 回退 | 触发 | 操作 |
|---|---|---|
| L0 软停用 | 合盖行为异常 | 在 `E:\.adds\reeden-kobo\userdata\` 建 **0 字节空文件** `no-sleep-cover`，重启生效；改用电源键。删掉即恢复 |
| L1 配置回退 | `turn-profile` / `wifi-handoff` 异常 | 写回 `sweep` / `keep`，或删除文件 |
| L2 冷重启 | 单次会话状态错乱 | **先退出回 Nickel 主页**再重新进入 |
| L3 备份回滚 | 升级后核心功能不达标 | 用 `reeden-kobo-backup-*` 覆盖回 community.1 + 3 热补丁 |
| L4 整包重装 | FAT32 损坏 / SHA256SUMS 截断 / run.sh 损坏 / L3 失败 | `chkdsk E: /F` → 删旧目录 → robocopy 整包 → 恢复 userdata → `Write-VolumeCache -DriveLetter E` → 安全卸载 |
| L5 恢复出厂 | 仅当 L0~L4 全失败且**书面批准** | ⚠️ 会清空 `E:\书\` 并可能变更固件；执行前再次确认备份可读，执行后本轮验收作废 |

```powershell
$path = "E:\.adds\reeden-kobo\userdata\turn-profile"
$bytes = [Text.Encoding]::ASCII.GetBytes("sweep")
$fs = New-Object IO.FileStream($path,[IO.FileMode]::Create,[IO.FileAccess]::Write,
        [IO.FileShare]::None,4096,[IO.FileOptions]::WriteThrough)
try { $fs.Write($bytes,0,$bytes.Length); $fs.Flush($true) } finally { $fs.Dispose() }

Write-VolumeCache -DriveLetter E
```
