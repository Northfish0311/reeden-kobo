# 安装后资源缺失：排查与恢复

## 已确认的反馈

2026-11-05 收到 v0.7.7 安装用户的自检日志。480 个安装文件中有 6 项失败，具体错误为 `No such file or directory`，而非已存在文件的内容不匹配。它们是以下三个资源在 `core/data/flutter_assets/` 与 `ui-assets/` 下各缺一份：

- `lib/common/widgets/theme_effect/theme_scaffold_ripple.frag`
- `packages/flutter_math_fork/lib/katex_fonts/fonts/KaTeX_Script-Regular.ttf`
- `packages/liquid_glass_renderer/lib/assets/shaders/liquid_glass_final_render.frag`

宿主、官方两份核心库和加载器在该日志中通过校验。反馈固件为 `4.42.23291`。

## 排查结果与边界

- 官网当前 Kindle 核心为 `1.43.2+791`。三个资源在官方 ZIP 中均存在、CRC 和 SHA 正确，普通文件属性正常。
- 使用重新从 GitHub 下载的原样 v0.7.7、实际官方 791 和实际依赖，在产品代码 393 / 固件 `4.46.23836` 上清除旧安装后执行 SSH 全新安装：480 项校验通过、首帧启动成功、首次运行后和返回原生界面后再次校验通过。
- 该实测未复现第三方文件自行消失；用户的旧固件、USB 传输及其具体环境不能由此认定已经复测。
- Nickel 曾有清理已索引图片资源的公开历史问题，但没有足够证据把它与本次 `.frag` / `.ttf` 缺失建立因果关系。因此没有将“修改扫描正则”当作已验证的修复。

目前确认的是资源缺失这一失败模式，尚未锁定文件最初丢失的环节。本次修复提供受完整性校验约束的恢复能力和更准确的诊断，不宣称已查明第三方环境的唯一根因。

## v0.7.8 如何处理

电脑组包时，在官方资源校验及字体适配完成后，生成本地的 `integrity/resources.tar.gz`。它保存本次安装实际使用的 `core/data/` 和 `ui-assets/` 资源，本身也列入最终 `SHA256SUMS`。归档只在用户电脑组包时产生，官方闭源文件不会进入本项目 Git 仓库或公开适配器附件。

每次启动（包括已有 `state/install-verified` 标记时）仍检查当前安装：

1. 验证恢复脚本及本地恢复归档与安装清单一致。
2. 仅对清单中属于资源目录的**缺失文件**恢复：先提取至临时文件，验证原 SHA 后独占创建目标，避免覆盖并发创建的文件；写入失败或中断仍会被完整校验拦截。
3. 已存在但内容不同的文件、程序二进制、脚本、用户书籍、笔记和设置不会被此机制覆盖。
4. 最后重新执行整个安装清单校验；仍有任何失败，继续拒绝启动，并记录具体路径。

不重写 `SHA256SUMS`，不忽略报错，也不会因为“以前校验成功过”就跳过本次检查。活动阅读会话不允许执行资源恢复。

自检菜单显示 `build-info.json` 的实际版本，失败时显示具体失败或缺失文件；完整输出保存在一次失败启动后的 `.adds/reeden-kobo/install-verification.log`。

## 使用与诊断

旧版用户先正常退出 Reeden，再运行新版一键安装器的保留数据升级流程。安装器会重建完整安装并添加恢复归档，不需要用户自己下载、寻找和补写六个资源。

若归档损坏或丢失、已有文件内容发生变化，或者缺失项属于可执行程序，仍需通过电脑安装器重新安装或升级；资源恢复机制不会把这些情况直接放行。传输结束后仍须安全弹出 USB。
