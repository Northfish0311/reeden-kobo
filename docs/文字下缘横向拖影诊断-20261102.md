# 文字下缘横向拖影：证据与受控修复候选

本次对象是白底文字每行下方的灰色横影，不是竖向分段接缝。停止以速度、分段数量或异步架构为主要优化目标。以下明确区分代码、设备读数与光学结果。

## 当前结论

尚未证明横影属于物理墨水残留，也没有证明 Flutter 渲染错误。当前最有证据的路径差异是：白底动画请求 raw 8 / PARTIAL，普通白底阅读请求 raw 4 / FULL；公开同系列内核只有后者启用普通 REAGL 补偿。动画还设置 CFA_SKIP，普通路径没有，两者不能被视为同一种刷新。

已准备默认关闭的 REAGL 分段候选：原分段、间隔、方向和缓冲管理保持不变，白底改 raw 4 / FULL，黑底 raw 9 / FULL；灰阶仍 CFA_SKIP。这是一项待光学验证的修复，不代表已达到“下缘干净”的验收目标。

用户随后明确要求先修复设备、保留动画，因而本轮后段已获安装授权：设备单独开启该候选，未关闭动画，未安装 timed 调度配置，未开启像素抓取。曾短暂启用动画后的 Q 对照，因不良反馈已撤回，最终设备仅保留 R。原“仅本地、禁止自动部署”适用于授权前；未推送或发布 GitHub。

## raw 8/9：实际内核证据优先

[NickelDissolve ABOUT.md](https://github.com/nicoverbruggen/NickelDissolve/blob/3449254ef098a4360ff5264abc34cda92f994de4/ABOUT.md) 把其日间 raw 8 称为 glkw16，并提醒 libkobo 与内核命名可能不同。但这条命名解释与本机实时导出的映射不一致，不能直接当成本机事实。

设备 `/sys/devices/platform/14000000.hwtcon/waveform_modes` 读数：

| 请求号 | user 名称 | driver 号 | E Ink 文件索引 |
|---|---|---|---|
| 4 | glr16 | 4 | 4 |
| 8 | gck16 | 8 | 8 |
| 9 | glkw16 | 9 | 9 |

`force_update_mode=-1`，没有全局强制模式；CFA 为 EINK_NORMAL，MDP 输入 ABGR32。没有修改任何映射或 sysfs 参数。

进一步读取 [Kobo 公开 MT8113 内核包](https://github.com/kobolabs/Kobo-Reader/tree/7a762964e7fa71ad8e8df50dd1b6eee721a43217/hw/mt8113-libraC_vision7)，仅提取研究所需 HWTCON 源码：

- `include/linux/hwtcon_ioctl_cmd.h:72`：枚举 8=GCK16、9=GLKW16。
- `hwtcon_fb.c:557`：请求值先通过 user→driver 映射；不能只看枚举或 libkobo 名称。
- `hal/hwtcon_wf_lut_config.c:847`：正式 CFA 表按波形文件版本关联 slot；运行时文件版本、温度和映射共同决定实际驱动。
- `hwtcon_core.c:1838` 的 `hwtcon_core_use_regal` 对 4、9、11 返回补偿模式，8 不在该分支。这是源码事实，不是对本机实际光学补偿强度的测量。
- `hwtcon_mdp.c` 的 CFA、旋转、灰阶量化在内部缓冲进行。`/dev/fb0` 并非最终电压序列或内部 Y4/CFA 输出，干净 framebuffer 不能独自证明“纯物理墨水问题”。
- 内核有队列合并代码；独立 marker 不能证明每个区域都独立显示。现有日志尚不能确认本次动画实际合并了哪些条带。

未复制这些 GPL 实现到 MIT 适配层，也未修改内核、固件或 Reeden 官方二进制。没有根据名字盲目交换 8/9。

## 像素、缓冲和等待链路

Flutter BGRA → 按输入 row stride 拷入紧凑 pending → 与 committed 比较 → 等上一批 marker → 写 RGB framebuffer → 逐区域 SEND → WAIT_SUBMISSION → 等所有已接受 marker COMPLETE → 提交 committed。

- 用户态转换逐像素交换 B/R，按字段打包；夜间互补灰阶配合硬件反相。没有向下移动、卷积锐化或额外阴影绘制，正常抗锯齿灰阶被保留。
- final framebuffer 在整段动画期间保持同一幅最终图像；每个分段不是重新拼接一幅新旧混合图。本地 mock 对每次调用检查所有在途数据不被覆盖。
- WAIT_SUBMISSION 不等于屏幕稳定；最终等待全部 accepted marker。驱动内部处理和光学稳定仍需实机采样。
- 前轮隔离分支已修复“等待失败前推进 committed”和“等待被拒绝 marker”的错误路径；本次以该分支为基础，未覆盖原 main 工作区。

## 假设判别

| 观察 | 可以支持的判断 | 不能直接推出的判断 |
|---|---|---|
| target BGRA 本身有同样灰影 | 先查 Flutter、主题、字体抗锯齿或透明度 | 不能直接怪波形 |
| target 干净，转换 framebuffer 新增灰影 | 查 stride、偏移、字段、反相与写入区域 | 不能直接怪墨水 |
| 两者干净，实拍有灰影 | 问题在用户态 framebuffer 之后 | 还包括驱动 MDP/CFA，不仅是物理残影 |
| 实拍阴影对应 old-only 字形，连续翻页累积 | 物理/驱动历史补偿问题更可信 | 只比较同一行基线不够，两页往往共享行位置 |
| 同图普通高质量刷新后消失 | 支持刷新路径相关问题 | 仍需排除模式/CFA差异，不能只凭“刷新好了”定位某个 LUT |

## 可控实验与同页 A/B

所有新选项默认关闭；`REEDEN_TURN_PROFILE` 默认仍为 stable。以下是独立启动配置，切换前正常退出，禁止同时运行两个 host。

| 组 | 参数 | 白底请求 | 比较目的 |
|---|---|---|---|
| N 普通 | `REEDEN_TURN_PROFILE=off` | 普通 raw 4 / FULL / flags 0 | 正常阅读基线 |
| S 原动画 | `REEDEN_TURN_PROFILE=stable`，其余新选项不设 | raw 8 / PARTIAL / CFA_SKIP | 保留旧动画 |
| T timed | `REEDEN_TURN_PROFILE=timed`，显式选相同分段/跨度 | raw 8 / PARTIAL / CFA_SKIP | 仅排除时序影响，非本轮主优化 |
| R 补偿分段 | stable + `REEDEN_TEXT_BAND_PATH=reagl` | raw 4 / FULL / CFA_SKIP | 分段与速度不变，测试补偿路径；当前设备候选 |
| Q 动画后对照 | S + `REEDEN_TEXT_QUALITY_AFTER_TURN=1` | 动画全部完成后追加整页 raw 4 / FULL / flags 0 | 检验同幅图质量恢复能力；当前设备未开启 |

黑底 R/Q 均采用 raw 9 / FULL。彩色内容、擦除旧彩色、显式清屏、全局反相切换和不支持几何使用原有安全路径。R 限制为本机已测 1072×1448、rotate 3；没有任意波形编号输入。

每组从同一旧页 A 转至同一新页 B；字体、字号、背景、亮度、温度、阅读位置不变。先记录原始残留，不要先清屏。随后各组采用相同的一次初始化条件，再做 A→B、B→A 和连续 5 次，保存整个刷新过程以及结束 1 秒后的近照。N/S/T/R 的旧、新帧 RGB 哈希应一致；时间页脚等变化需注明或避开正文区域，不能悄悄称为全帧相同。

Q 应录慢动作，分别取最后一段完成、追加更新结束后的画面；它不是已证实有效的“无闪修复”，也不等于现有菜单“刷新”的清屏路径。Q 没有强制 GC16，不做每页黑白全闪，但实际是否出现可见闪动必须用视频确认。

## 像素证据开关

仅在另行授权的诊断运行中，准备一个已有的专用绝对目录，设置：

```sh
REEDEN_FRAME_EVIDENCE_DIR=/path/to/private-capture
REEDEN_FRAME_EVIDENCE_LIMIT=2
```

仅抓取有效翻页指令之后的大幅更新，普通 off 组也能抓取。每个独立事务包含：

- `old.bgra`：此前确认完成的逻辑图。
- `target.bgra`：最终逻辑图，在 framebuffer 写入前保存。
- `fb-before.bin`：转换前完整 framebuffer。
- `fb-converted.bin`：转换后、SEND 之前的完整 framebuffer。
- `fb-complete.bin`：所有刷新完成后的 framebuffer。
- `info.json` / `result.json`：几何、stride、字段、反相、区域、普通波形、profile、band_path、trace_id、完成结果。

原始 fb-before 可能仍采用上一图编码，不能用新反相标志直接解码为旧逻辑图，应直接使用 old.bgra。info.hw_inverted 描述目标帧编码。

抓取最多 1～4 次，默认 2 次；每次约 29.7 MiB，默认上限约 59.4 MiB（含有效旧图）。无新增全帧内存副本，但写盘会影响主线程时序；抓取运行不可用于宣称速度改善。目录及文件使用独占创建并拒绝末端符号链接；FAT 权限并不等价于保密，不能公开上传。

```sh
python3 scripts/analyze-frame-evidence.py CAPTURE_DIR --output NEW_ANALYSIS_DIR
python3 scripts/analyze-turn-trace.py current.log --evidence device --output trace.json
```

像素工具检查转换是否逐字节符合原逻辑、padding 是否保留、完成前后是否一致，并生成旧图、目标图、解码图、逐行灰度 CSV 和 old-only 字形候选掩码。不会抹掉灰阶或自动认定浅灰就是故障。存在目标透明像素时，应结合 alpha 分布再判断 Flutter 合成。

对应标记与 SEND / SUBMISSION / COMPLETE、波形、区域、模式、flags、返回值和耗时通过 `[turn-trace]` 记录。工具不把 marker 完成等同于光学稳定，也不把 mock 时间作为实机性能。

## 变更最小性、开销及风险

1. **R 优先**：不增加刷新请求、分段数、帧缓冲写入或额外全帧内存，改动仅波形与更新模式。可能增加驱动 REAGL 计算、等待和队列合并，实际试用确认横影减轻、动画与速度正常，但仍有淡字残留；不能宣称“零开销”或彻底修复。如果补偿对小区域边界有要求，效果可能不理想，应退回 S。
2. **Q 诊断备用**：明确增加 1 次整页 SEND + 1 次 COMPLETE 等待，没有重绘逻辑帧。本机 4 次实测增加约 329～353 ms；用户报告闪烁或明显变慢，因此已撤回，不推荐作为本机逐页修复。是否能清除横影没有独立确认。
3. **软件修复只在有证据时做**：若 target 自带异常，先修主题/合成；若转换新增异常，修对应转换。当前不量化、阈值化或删除字体抗锯齿，以免损失细节掩盖问题。
